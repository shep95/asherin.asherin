shepherd | aesthetics, visual psychology & interface design — root-layer research dataset
version: 1.0 | compiled: 2026-10-25 | format: plain text | language: english
scope: website, software, app, dashboard, product and professional interface visual design

PURPOSE
a reusable research dataset, not a universal formula for beauty. every record travels from surface observation to plain-English explanation, perception, cognition, root mechanism, interface rule, example, real-world scenario, tradeoff, and test.

EVIDENCE LEGEND
quantitative law = constrained measurable relationship; empirical phenomenon = observed research pattern, context varies; explanatory theory = plausible framework with supporting research; gestalt principle = perceptual organization tendency; design heuristic = useful practice, not immutable rule; normative standard = published accessibility criterion; contextual tendency = influenced by culture, user and task.
source origin note: the user’s shepherd knowledge file explicitly specifies dark/cold/cinematic styling, domain-native interface cognition, aesthetic pattern recognition, interface quality tokens, and mechanism-first decomposition. those are treated here as project preferences and design-process inputs, not universal empirical psychological facts. the zophiel-vadic forecasting file is not a scientifically established source of interface aesthetics and is not used as such.

ROOT MODEL
stimulus (pixels, words, geometry, motion) -> visual encoding (contrast, shape, grouping) -> attention and interpretation -> emotion / expectation / judgment -> action and error -> measured outcome / feedback. arrows represent a useful analysis model; actual neural processing is recurrent and context-dependent.

PRACTICAL INTERPRETATION
surface = what a designer notices; plain = explain as to a beginner; layer 1 = sensory/perceptual mechanism; layer 2 = psychological mechanism; layer 3 = deepest useful causal root (not speculative neuroscience); action = design translation; scenario = concrete use case; tension = where naive application fails; verification = what would test the claim.

RECORD 001 | foundations | aesthetic judgment
================================================================================================
EVIDENCE CLASSIFICATION:
empirical theory

LAYER 0 — SURFACE OBSERVATION:
people judge visual arrangements as pleasing or displeasing.

LAYER 0B — EXPLAIN LIKE I AM NEW:
beautiful means the arrangement feels rewarding to look at, not merely that it is fashionable.

LAYER 1 — SENSORY AND PERCEPTUAL MECHANISM:
visual features are encoded: shapes, contrast, contours, colors and regularities.

LAYER 2 — HUMAN COGNITIVE / EMOTIONAL INTERPRETATION:
expectations, fluency, novelty, emotion, memory and culture influence evaluation.

LAYER 3 — ROOT MECHANISM / BOUNDARY OF CLAIM:
aesthetic response emerges from interaction between stimulus, observer, task and context; no single universal beauty formula.

DESIGN APPLICATION / RULE:
design to the user’s task and cultural context; compare preferences across representative groups.

MICRO-EXAMPLE:
the same monochrome dashboard reads elegant to an analyst and cold to a child.

FULL SCENARIO:
a medical portal looks sleek but patients rate it unfriendly; add legible labels and reassuring explanation without abandoning visual restraint.

COUNTEREXAMPLE / LIMITS / CONFLICTING PRINCIPLES:
beauty and usability correlate in some settings but are not identical.

EMPIRICAL TEST / QUALITY GATE:
blind preference test followed by task usability test and subgroup analysis.

SOURCE / BASIS:
reber 2004; nng visual-design guidance

RECORD 003 | foundations | aesthetic-usability effect
================================================================================================
EVIDENCE CLASSIFICATION:
replicated usability phenomenon

LAYER 0 — SURFACE OBSERVATION:
attractive interfaces may be perceived as easier to use.

LAYER 0B — EXPLAIN LIKE I AM NEW:
people can confuse “looks easy” with “works easily.”

LAYER 1 — SENSORY AND PERCEPTUAL MECHANISM:
visual polish gives early signals before functional experience.

LAYER 2 — HUMAN COGNITIVE / EMOTIONAL INTERPRETATION:
positive affect colors perceived difficulty and tolerance for minor defects.

LAYER 3 — ROOT MECHANISM / BOUNDARY OF CLAIM:
first impressions alter expectations and reported experience; appearance does not repair fundamental accessibility or task failures.

DESIGN APPLICATION / RULE:
measure perceived usability independently of observed errors and task success.

MICRO-EXAMPLE:
an attractive banking app feels trustworthy at first, although a hidden transfer action causes errors.

FULL SCENARIO:
users rate a beautifully styled checkout highly while analytics show cart abandonment.

COUNTEREXAMPLE / LIMITS / CONFLICTING PRINCIPLES:
do not use attractiveness as evidence of safe or accurate operation.

EMPIRICAL TEST / QUALITY GATE:
paired visual ratings, task time, error rate, post-task usability score.

laws of ux; nngroup

================================================================================================
CROSS-DOMAIN SCENARIOS — MULTI-PRINCIPLE DECOMPOSITIONS
================================================================================================

SCENARIO 01 — nighttime cybersecurity operations dashboard
  surface: dark polished grid, dozens of threat rows, one critical alert.
  perception: restrained gray surfaces and strong alert contrast increase foreground segmentation; uniform table rhythm allows scanning.
  cognition: experienced operators chunk logs and prioritize anomalous states; unfamiliar decorative icons raise interpretation cost.
  root: the design must maximize correct detection and triage under cognitive and time pressure, not just produce a cinematic mood.
  actions: stable table columns, meaningful semantic colors, readable typography, visible timestamps, keyboard navigation, persistent action feedback.
  failure: all alerts use intense neon, creating equal salience and alarm fatigue.
  test: detection miss rate, triage time, false positives, contrast, task switching.

SCENARIO 02 — calm premium financial application
  surface: quiet typography, dark layered background, generous padding, single accent.
  perception: consistent boundaries, spacing and type hierarchy create an orderly figure-ground arrangement.
  cognition: polish shapes first impressions, but monetary trust requires auditability and understandable actions.
  root: perceived quality is an inference from cues; actual correctness is determined by operations and evidence.
  actions: show balances with timestamp, reversible edits, clear fee disclosure, explicit transaction states.
  failure: minimalist unlabeled transfer controls create errors despite visual praise.
  test: transfer success, fee understanding, reversibility, trust calibration.

SCENARIO 03 — medical appointment booking
  surface: available times, doctor card, confirm button, accessibility labels.
  perception: show selectable states and unambiguous groups rather than purely color distinctions.
  cognition: anxiety and working-memory burden favor visible context and clear next steps.
  root: visual systems must support reliable decision-making under variable stress and ability.
  actions: separate date/time selection, retain doctor and clinic info, show cancellation terms, make confirmation unmistakable.
  failure: tiny low-contrast chips and hidden clinic address increase booking errors.
  test: correct slot chosen, cancellation-policy comprehension, screen-reader workflow, error recovery.

SCENARIO 04 — creative studio portfolio
  surface: large expressive imagery, asymmetrical layout, custom display type.
  perception: intentionally broken symmetry directs gaze, while type hierarchy holds navigation together.
  cognition: controlled surprise signals creative identity; unfamiliar navigation increases search effort.
  root: novelty is valuable when it serves identity without blocking task completion.
  actions: expressive hero with conventional project list and obvious contact.
  failure: scroll-jacked animations reduce control and prevent content access.
  test: portfolio recall, project findability, reduced motion, contact completion.

SCENARIO 05 — dense enterprise analytics
  surface: nested charts, filters, metrics and tables.
  perception: alignment, common region and selective contrast reduce visual searching across dense information.
  cognition: professional users possess learned chunks and need comparative context.
  root: total cognitive work is not monotonically lower with fewer visible elements.
  actions: user-customizable density, sticky column headers, semantic grouping, keyboard filters.
  failure: spacious cards cause enormous scrolling and break side-by-side comparison.
  test: throughput, wrong comparisons, filter time, subjective mental effort.

SCENARIO 06 — mobile emergency response
  surface: one urgent action, short instructions, high contrast and clear location status.
  perception: large motor targets, clear figure-ground and persistent feedback make urgent controls visible.
  cognition: stress narrows attention and can increase errors.
  root: the interface is a human-in-the-loop safety mechanism under extreme conditions.
  actions: prioritize emergency action, prevent accidental destructive changes, readable offline/error status.
  failure: animated branding delays access or a tiny cancel target sits beside confirm.
  test: real-device accessibility, task time, erroneous taps, degraded network behavior.

================================================================================================
PROJECT-SPECIFIC VISUAL DESIGN DEFAULT (NOT SCIENTIFIC LAW)
================================================================================================
the shepherd source recommends a dark, cold, cinematic aesthetic: layered near-black surfaces, a restrained accent at trust states, thin lowercase typography, intentional negative space, architecture-like spatial organization. this is an expressive design direction, not a mandate for all interfaces. the usability constraints above can override it when text contrast, discoverability, safety, task density or a user’s preferences require.

IMPLEMENTATION AUDIT CHECKLIST
01. can the user identify the primary action within five seconds?
02. can users distinguish background, surface and interactive states?
03. are related objects closer to each other than unrelated objects?
04. do similar components reliably behave the same?
05. are fonts and contrast readable under actual device and lighting conditions?
06. is focus visible to keyboard users?
07. are color differences supplemented with labels, shape or text?
08. do pointing targets accommodate real motor use and spacing?
09. does every click produce honest, timely state feedback?
10. can dangerous actions be prevented or reversed?
11. does motion convey change rather than distract?
12. does mobile preserve critical task meaning?
13. does visual polish correlate with measured usability, rather than hide failure?
14. are taste, cultural assumptions and actual user populations separated?
15. are hypotheses measured with task accuracy as well as subjective preference?

QUANTITATIVE REFERENCE NOTES
fitts: movement time MT = a + b*log2(1 + D/W), where D is distance, W effective target width and a,b are empirically fitted; valid under experimental conditions. do not invent a,b.
hick–hyman: reaction time RT ≈ a + b*log2(N+1) for N approximately equally probable stimulus–response choices under suitable conditions; general products depart from laboratory assumptions.
weber: delta-I / I ≈ k over suitable perceptual ranges; not a universal cross-color contrast rule.
wcag 2.2 aa text contrast: 4.5:1 for standard text, 3:1 for large text (with exceptions); non-text UI component contrast 3:1 where the relevant success criterion applies. wcag 2.2 aa pointer target criterion generally 24x24 CSS px or exceptions including spacing. these are conformance thresholds, not all-purpose optimal target sizes.
miller 7±2 is not a universal menu design count; working-memory capacity depends on chunking and task. exact luxury ratios and claims that particular colors produce the same emotion in everyone are not established universal laws.
